## 1. システム全体構造 & レイヤー設計

Rooney は純粋な Rust と `libcosmic` を基盤に、以下の 4 つの独立したコアレイヤーで構築されています：

```text
┌────────────────────────────────────────────────────────┐
│                   UI / View Layer                      │
│ (libcosmic, Titlebar, TabBar, SidebarTree, SplitPane)  │
└──────────────────────────┬─────────────────────────────┘
                           │ Event Dispatch / Message Flow
┌──────────────────────────▼─────────────────────────────┐
│                 Editor Canvas Core                     │
│  - Viewport Virtualization (< 0.40 ms Layout)          │
│  - LineWrapModel (Sparse O(log W) Cumulative Wrap)     │
│  - Caret & Selection Engine (Unicode Graphemes)        │
└──────────────┬──────────────────────────┬──────────────┘
               │                          │
┌──────────────▼────────────┐ ┌───────────▼──────────────┐
│ Buffer Layer (Piece-Tree) │ │ Generation-Tracked Async │
│ - ropey::Rope             │ │ - Tree-sitter AST Parser │
│ - O(1) Max Line Tracking  │ │ - Markdown GFM Parser    │
│ - Atomic Safe File I/O    │ │ - Regex & String Search  │
└───────────────────────────┘ └──────────────────────────┘
```

## 2. 統一世代管理非同期パイプライン

巨大ファイル（> 2MB〜50MB）の構文解析や検索走査を同期実行すると、UI スレッドが数十〜数百ミリ秒ブロックされ、タイピングの引っかかりやフレーム落ちが発生します。Rooney ではこれらを完全に解決するため、**整数世代カウンターによる非同期パイプライン** を採用しています。

- **非同期ワーカースレッド**:
  - Tree-sitter AST 構文解析
  - Markdown GFM ドキュメントパース
  - 全バッファに対するインクリメンタル検索
  これらをすべて `tokio::task::spawn_blocking` へ移譲。
- **決定論的世代カウンター (`GenerationId`)**:
  - `parse_generation`: テキスト変更ごとにインクリメント
  - `markdown_generation`: プレビュー切替・編集・仕様切替ごとにインクリメント
  - `search_generation`: 検索クエリ入力ごとにインクリメント
- **競合・遅延スナップショットの破棄 (Stale Protection)**:
  - ワーカースレッドから解析結果が UI スレッドへ戻った際、現在のバッファ世代と結果の世代が一致しない場合、タイムスタンプに依存することなく即座に結果を破棄します。
  - これにより、高速タイピング中やファイル切替時にも古いハイライトがフラッシュして上書きされる現象を 100% 防止します。

## 3. ビューポート仮想化 & 累積折り返しモデル (`LineWrapModel`)

### ビューポート仮想化
- 185万行（50MB）の巨大テキストであっても、実際にレイアウト計算・グリフ描画を行うのは **「現在の画面内に収まる可視行 ＋ 上下マージン数行」** のみに限定されます。
- これにより、レイアウト計算時間は常に **サブミリ秒（< 0.40 ms）** で完了し、144+ FPS の高リフレッシュレート環境でも一切の引っかかりのない描画を提供します。

### 累積折り返しモデル (`LineWrapModel`)
- 長い行が折り返される際、従来の単純な行高さ計算では折り返し行と後続行の Y 座標が重複する不具合が発生しやすい課題がありました。
- Rooney では疎な $O(\log W)$ の `LineWrapModel` を実装。折り返し行のサブ行数を累積加算し、正確な描画 Y 座標とサブピクセル精度のマウスヒットテスト（クリックした位置へのキャレット正確配置）を実現しています。

## 4. ピースツリー Rope バッファ & 編集エンジン

- **ピースツリー構造 (`ropey`)**:
  - テキストを行とピースの平衡木として保持することで、大容量ファイルに対する文字挿入・削除操作に伴う連続メモリの再配置を完全に排除。
- **最大行長追跡**:
  - 各行のバイト長・文字長を $O(1)$ で追跡し、ウィンドウリサイズ時のソフトラップ再計算を最小限のオーバーヘッドで実行。
- **アトミック保存**:
  - 保存時は直接対象ファイルを上書きせず、同階層の一時ファイル（`.{filename}.tmp.{pid}`）へ書き込み・`sync_all` を実行した後にアトミックリネームで置換します。

---

## 5. 実グリフメトリクス計測キャッシュ (`cosmic-text`)

- **等幅近似の限界を克服**:
  - 一般的な等幅エディタでは「全角文字は半角の2倍」という単純計算を行うことが多く、全角ダッシュ（`――`）、CJK 記号、Ambiguous 文字でカーソルと文字の表示位置がずれる問題が発生します。
- **実描画メトリクスの参照**:
  - Rooney では `cosmic-text` が実際にシェーピング・レイアウトした実グリフ幅を直接参照。
  - `RwLock` によるスレッドセーフな共有キャッシュ機構、Tab / ASCII / CJK の高速パスを備え、描画パフォーマンスを損なうことなく完璧なキャレット位置整合性を担保します。

## 6. ローカル AI 統合 (Ollama SSE ストリーミング)

- **完全オフライン動作**:
  - `reqwest` を用いてローカルの Ollama デーモン（`http://127.0.0.1:11434`）と通信。
- **FIM (Fill-in-the-Middle)**:
  - カーソル前の `prefix` とカーソル後の `suffix` を抽出し、Ollama の FIM プロンプトフォーマットに整形してコード中間補完を生成。
- **Server-Sent Events (SSE) ストリーミング**:
  - チャット応答は非同期ストリームとしてトークン単位でリアルタイム受信・キャンバス描画。ユーザーによる途中中断（キャンセル）も瞬時に反映されます。
